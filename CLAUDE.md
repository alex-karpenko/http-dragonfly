# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

http-dragonfly is an HTTP request splitter/router/relay proxy (Rust, single crate, edition 2021). Behavior is entirely config-driven via YAML (root key `listeners`) — response strategies, `jq`-style `condition` predicates (via `jaq`), and `${CTX_*}` context variable substitution are all documented in README.md; read it before changing config parsing or routing behavior.

## Build, test, lint

- `cargo build`
- `cargo test` — runs unit tests (insta snapshots under `src/**/snapshots/`), a glob test over every fixture in `tests/configs/good/*.yaml` and `tests/configs/wrong/*.yaml` (via `insta::glob!` in `src/config.rs`), and integration tests (`tests/basic.rs`, `tests/tls.rs`) that spin up an echo server and drive `http_dragonfly::run()` directly.
- `cargo fmt --all -- --check` and `cargo clippy --all-targets -- -D warnings` — both enforced in CI; clippy denies all warnings.
- `pre-commit run --all-files` — also run before considering a change done (fmt, check-yaml/toml/json, trailing-whitespace, secret detection; configured in `.pre-commit-config.yaml`).

## Testing conventions

- When `cargo test` produces new or changed insta snapshots, show the diff and ask before accepting — don't run `cargo insta accept`/`cargo insta review` unattended.
- New fixtures for the config glob tests go in `tests/configs/good/` (should parse successfully) or `tests/configs/wrong/` (should fail validation) — `src/config.rs`'s test picks up new files automatically.

## Commit conventions

Conventional Commits (`feat:`, `fix:`, `fix!:` for breaking changes, `chore:`, `test:`, etc.) — `cliff.toml` parses these into CHANGELOG.md sections at release time via git-cliff. PR-merge commits end with `(#NN)`.

## Releases

CHANGELOG.md is generated by git-cliff and committed manually before tagging (no CI workflow writes it back). Pushing a `vX.Y.Z` tag triggers `publish-release.yaml` (GitHub release using git-cliff output as the body) and `publish-image.yaml` (Docker image to `ghcr.io`, cosign-signed). See the `/release` skill for the full step-by-step.
